# 会員ごとの貸出上限 仕様書

## 1. 目的・背景
一部の会員が多くの本を借りたままにすると、他の会員が借りられなくなる。会員ごとに同時に借りられる冊数に上限を設け、蔵書を公平に利用できるようにする。

### スコープ
- 対象: 貸出時（POST /api/loans・蔵書画面の「貸出」）の上限チェックと、上限到達時のエラー応答・画面表示
- 対象外: 返却・蔵書登録・会員登録・貸出期間（14 日）・延滞判定の変更、会員ごとに異なる上限、上限の変更画面、予約、貸出期間の延長、ログイン・権限管理

## 2. 用語
| 用語 | 意味 |
| --- | --- |
| 貸出中の冊数 | その会員の貸出（loans）のうち、返却日時（returned_at）が未設定のものの件数。延滞中の貸出も含む。返却済みの貸出は含まない。同じ本を複数冊借りている場合もそれぞれ 1 冊と数える |
| 貸出上限 | 会員 1 人あたり、同時に貸出中にできる冊数。**ちょうど 3 冊**（3 冊までは借りられ、4 冊目は借りられない） |
| 在庫 | 蔵書画面の「在庫」列に「貸出可能数 / 所蔵数」で表示される値 |

## 3. 操作経路と表示先
- 貸出: ヘッダーの「蔵書」→ 蔵書一覧の対象の本の行で、会員選択プルダウンから会員を選ぶ →「貸出」ボタンを押す
- 貸出のエラー表示: 蔵書画面の検索欄の下、蔵書一覧の表の上に、赤字でエラーメッセージを 1 行表示する
- 返却: ヘッダーの「貸出」→「貸出中の本」の表の対象の行で「返却」ボタンを押す
- 貸出状況の確認: 「貸出」画面の「貸出中の本」の表（本・会員・貸出日・返却期限・状態）と「返却済みの履歴」の表（本・会員・貸出日・返却日）

## 4. 機能要件

### 4.1 貸出（上限チェック）
| ID | 条件・操作 | 期待される結果 |
| --- | --- | --- |
| LIM-01 | 貸出中の冊数が 0〜2 冊の会員で、在庫の貸出可能数が 1 以上の本の「貸出」を押す | 貸出が 1 件記録される。API は HTTP 201 を返す。蔵書画面でその本の貸出可能数が 1 減る（例: 4 / 4 → 3 / 4）。貸出画面の「貸出中の本」に 1 行追加され、本のタイトル・会員名・貸出日（当日）・返却期限（貸出日の 14 日後）・状態「貸出中」が表示される。エラーメッセージは表示されない |
| LIM-02 | 貸出中の冊数が 3 冊の会員で、在庫の貸出可能数が 1 以上の本の「貸出」を押す（4 冊目） | 貸出は記録されない。API は HTTP 409 と本文 `{"error":"貸出上限（3冊）に達しているため貸し出せません"}` を返す。蔵書画面に「貸出上限（3冊）に達しているため貸し出せません」と赤字で表示される。その本の貸出可能数は変わらない。貸出画面の「貸出中の本」の行数も変わらない |
| LIM-03 | 会員 A が 3 冊借りている状態で、別の会員 B（貸出中 0〜2 冊）が「貸出」を押す | 会員 B は LIM-01 のとおり貸出できる（上限は会員ごとに数える） |

### 4.2 返却後の状態
| ID | 条件・操作 | 期待される結果 |
| --- | --- | --- |
| LIM-04 | 貸出中の冊数が 3 冊の会員の貸出のうち 1 件を、貸出画面で「返却」する | その貸出に返却日時が記録される。その行は「貸出中の本」から消え、「返却済みの履歴」に本・会員・貸出日・返却日（当日）が表示される。蔵書画面でその本の貸出可能数が 1 増える。その会員の貸出中の冊数は 3 → 2 になる |
| LIM-05 | LIM-04 の後、同じ会員で在庫のある本の「貸出」を押す | LIM-01 のとおり貸出できる（貸出中の冊数は 2 → 3 になる）。さらにもう 1 冊借りようとすると LIM-02 のとおり拒否される |

### 4.3 判定の順序とエラー応答
POST /api/loans は、次の順に判定し、最初に当てはまったエラーだけを返す。どのエラーの場合も貸出は記録されず、在庫も変わらない。

| 順序 | 条件 | HTTP | 本文の error |
| --- | --- | --- | --- |
| 1 | bookId または memberId が未指定 | 400 | `bookId and memberId are required` |
| 2 | 指定した本が存在しない | 404 | `Book not found` |
| 3 | 指定した会員が存在しない | 404 | `Member not found` |
| 4 | 本の貸出可能数が 0 | 409 | `No available copies of this book` |
| 5 | 会員の貸出中の冊数が 3 冊以上（上限到達） | 409 | `貸出上限（3冊）に達しているため貸し出せません` |

- 在庫切れ（順序 4）と上限到達（順序 5）が同時に当てはまる場合は、在庫切れを返す。
- 画面では、在庫の貸出可能数が 0 の本は「貸出」ボタンが押せない（無効表示）。会員を選ばずに「貸出」を押した場合は、API を呼ばずに「貸出先の会員を選択してください」と表示する（いずれも既存の動作のまま）。

## 5. 既存機能への影響・互換性
- 変更するのは貸出 API（POST /api/loans）の判定だけ。上限到達時に、これまでは成功していた 4 冊目以降の貸出が HTTP 409 で拒否されるようになる。
- データベースのテーブル構成（books / members / loans）は変更しない。データ移行は不要。
- 変更時点で既に 4 冊以上借りている会員がいても、その貸出はそのまま残り、返却もできる。新しい貸出だけが、貸出中の冊数が 3 冊未満になるまで拒否される。
- 返却 API・貸出一覧 API・蔵書 API・会員 API の入出力は変更しない。

## 6. 非機能要件
- 権限: 本システムにはログイン・権限管理がなく、全操作を職員が行う前提。本変更で権限は変えない。
- 同時実行: バックエンドは単一プロセスで、SQLite（node:sqlite）への処理を同期的に 1 リクエストずつ実行するため、上限判定と貸出記録の間に別の貸出が割り込むことはない。複数プロセス構成への対応は対象外とする。
- 性能: 上限判定は会員 1 人分の貸出件数を数えるだけで、性能への影響はない。

## 7. データの保存と初期化
- データは SQLite のファイル（backend/data/library.db）に保存される。
- ローカル環境ではファイルが残るため、サーバーを再起動してもデータは保持される。
- デモ環境（Render の Free プラン）は永続ディスクを使わないため、サービスの再起動・再デプロイのたびにデータが消え、シードデータ（本 6 冊・会員 3 名）が再投入される。

## 8. 受け入れテストの前提
- デモ環境（https://demo-library-system.onrender.com/ ）で、画面操作だけで確認する。
- テストで使う本・会員は、テストの中で画面から新しく登録する（名前に識別子を含め、既存データと区別する）。
- 同じ会員に複数冊貸し出すため、本は所蔵数 4 以上で登録する。
